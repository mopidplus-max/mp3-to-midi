# mp3 → midi: своя модель, обученная на GitHub-раннере

Два workflow:

| Что | Файл | Когда запускать |
|---|---|---|
| **1. Обучение** своей модели на синтетике (60k+ вариантов mp3+midi) | `.github/workflows/train.yml` | хочется свой чекпойнт и живые кривые loss |
| **2. mp3 → midi** готовой моделью (официальная Basic Pitch) | `.github/workflows/infer.yml` | нужен нормальный MIDI прямо сейчас |

---

## 0. Что реально умеет раннер

`ubuntu-22.04`: 4 vCPU, 16 ГБ RAM, ~14 ГБ диска, **без GPU**, джоб убивается на ~6 часах.
Публичные репозитории — бесплатно и без лимита минут.

Отсюда арифметика про 60 000 треков:

- один трек 6–14 с: рендер + шум + двойной прогон через mp3 ≈ **0.3–0.6 с** на 4 процессах → ~8–12 треков/с в теории, по факту меньше;
- 60 000 × 10 с ≈ **8–9 ГБ** на диске — влезает, но впритык;
- по времени: 60 000 треков ≈ **2–3 часа** только генерации, плюс обучение. В один 6-часовой джоб **не влезает**.

Поэтому: за один запуск генерится столько, сколько влезает в `gen_minutes` (по умолчанию 20 000 за ~60 мин), остальное время учится. Хочется все 60k — три запуска: каждый со своим `seed` даёт новый срез музыки, а `init_from_url` продолжает обучение с прошлого чекпойнта.

Скорость генерации пишется в `data/gen_stats.json` — после первого запуска поставь `count` по факту.

---

## 1. Что генерируется (это главное)

Каждый трек собирается случайно, в `scripts/generate_data.py`:

- **стиль**: джаз, поп, рок, электроника, латина, эмбиент — у каждого свой темп, свинг, гармонические последовательности, плотность мелодии;
- **инструменты**: случайные программы General MIDI — пианино, электропиано, гитара (нейлон/электро), струнные, духовые, орган, синты; отдельно для мелодии, аккордов и баса;
- **барабаны**: случайный паттерн на GM-перкуссии — бочка, снейр, клэп, закрытый/открытый хэт, райд, томы, сбивки; в ~15% треков их нет;
- **гармония**: тональность, лад (мажор/минор/дорийский), аккорды (трезвучия, септаккорды, sus4, add9), обращения;
- **аудио-деградации**: белый шум с SNR 12–40 дБ, случайная громкость и клиппинг, реверберация и хорус fluidsynth, **прогон через mp3** (64–192 кбит/с) — чтобы модель видела «грязный» звук, а не только идеальный WAV.

Барабаны специально **не попадают в разметку** (в ней только высотные ноты) — модель должна научиться их игнорировать.

## 2. Быстрый старт

1. Форкни/залей репозиторий себе.
2. **Actions** → **«2. mp3 → midi (готовая модель)»** → **Run workflow**:
   - кинуть mp3 в папку `input/` (workflow стартует сам на push), или
   - вставить прямую ссылку в `audio_url`.
3. Через 3–5 минут: **Artifacts** → `midi-<номер>.zip`.

Локально:

```bash
pip install -r requirements.txt
pip install basic-pitch==0.4.0 --no-deps
python scripts/infer.py song.mp3 -o midi/
```

## 3. Обучение своей модели

**Actions** → **«1. Обучить свою модель»** → **Run workflow**.

| Параметр | Смысл | Дефолт |
|---|---|---|
| `count` | сколько треков сгенерировать в этом запуске | 20000 |
| `gen_minutes` | бюджет на генерацию | 60 |
| `minutes` | бюджет на обучение | 240 |
| `seed` | сид генератора (пусто = номер запуска) | — |
| `max_seconds` | макс. длина трека | 14 |
| `batch_size` / `learning_rate` / `steps_per_epoch` | гиперпараметры | 8 / 0.001 / 200 |
| `init_from_url` | ссылка на `checkpoint.tar.gz` прошлого запуска | — |

Что происходит:

1. ставятся TensorFlow 2.15, fluidsynth, саундфонт, ffmpeg;
2. генерируется датасет (см. раздел 1), параллельно на всех ядрах;
3. модель Basic Pitch (CQT + свёртки, ~17k параметров) учится на окнах по 2 секунды;
4. по истечении `minutes` обучение **само** останавливается, чекпойнт сохраняется;
5. модель экспортируется в `out/saved_model`, на двух валидационных треках делается демо (`demo/*.wav`, `*_predicted.mid`, `*_reference.mid`);
6. чекпойнт уходит в релиз `ckpt-<номер>` — ссылку на него можно вставить в `init_from_url` следующего запуска.

Артефакты: `out/**` (чекпойнт, SavedModel, CSV с loss) и `demo/**`.

---

## 4. Что получится и чего не получится

Честно:

- **Это не замена Basic Pitch.** Тот обучен на ~300 часах реальных записей на GPU; мы — на синтетике на четырёх ядрах.
- Модель выучит **синтетические** инструменты и стили, включая барабаны как «шум, который надо игнорировать». На реальном mp3 качество будет заметно хуже.
- `val_loss` падает уже на первых минутах — это проверка, что весь путь «генерация → обучение → экспорт → MIDI» живой.
- После ~5 часов: несколько тысяч шагов, десятки тысяч 2-секундных окон. Для узкого домена это уже осмысленно.

Если нужен реальный результат — ветка развития такая: те же скрипты на бесплатном GPU (Colab/Kaggle T4), больше данных (`count` 100k+), и дообучение с весов официальной модели.

## 5. Файлы

```
.github/workflows/train.yml   обучение (workflow_dispatch)
.github/workflows/infer.yml   mp3 → midi (push в input/ или вручную)
scripts/generate_data.py      генератор: стили, инструменты, барабаны, шум, mp3
scripts/common.py             MIDI → onset/note/contour, нарезка окон
scripts/train.py              обучение с лимитом по времени + экспорт модели
scripts/infer.py              аудио → MIDI (своя или готовая модель)
scripts/make_demo.py          демо: wav + предсказанный и эталонный midi
scripts/prepare_data.py       альтернатива: реальные MIDI (MAESTRO) вместо синтеза
scripts/report.py             итоги в GitHub Step Summary
```

Локально:

```bash
python scripts/generate_data.py --out data --count 300 --minutes 10
python scripts/train.py --data data --out out --minutes 20 --steps-per-epoch 50
python scripts/infer.py demo/track.wav -o midi/ --model-path out/saved_model
```

## 6. Грабли

- `basic-pitch` ставить с `--no-deps`: иначе pip тянет `tflite-runtime` (только Python < 3.11) и падает.
- TensorFlow строго **2.15.0** — с 2.16 basic-pitch 0.4.0 не работает.
- fluidsynth в CI рендерит «в файл» (`-F`), звуковая карта не нужна.
- Барабаны идут отдельным инструментом с `is_drum=True` — в разметку они не попадают намеренно.
- Если обучение упало, чекпойнт прошлой эпохи всё равно лежит в `out/checkpoints` в артефактах.
- Данные между запусками не кэшируются (8 ГБ в кэш не влезут) — каждый запуск генерит свой срез с новым сидом.
