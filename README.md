# mp3 → midi: своя модель, обученная на GitHub-раннере

Два готовых workflow:

| Что | Файл | Когда использовать |
|---|---|---|
| **1. Обучение** своей модели с нуля на синтезированном пианино (MAESTRO) | `.github/workflows/train.yml` | хочется именно *свой* чекпойнт и посмотреть, как loss падает |
| **2. mp3 → midi** готовой моделью (официальная Basic Pitch) | `.github/workflows/infer.yml` | нужен нормальный MIDI из трека прямо сейчас |

---

## 0. Сразу честно: что умеет бесплатный раннер

`ubuntu-latest` / `ubuntu-22.04`:

- 4 vCPU, 16 ГБ RAM, ~14 ГБ диска
- **нет GPU**
- жёсткий лимит ~6 часов на джоб (я ставлю 350 минут и останавливаю обучение сам, чтобы чекпойнт не потерялся)
- 2000 минут в месяц на приватные репозитории (публичные — бесплатно и без лимита)

Из этого следует:

- **Обучить с нуля модель уровня Spotify Basic Pitch тут нельзя.** Оригинал учили на сотнях часов аудио на GPU.
- **Можно** обучить маленькую модель на узком домене (пианино) и увидеть, что она реально начинает слышать ноты.
- **Можно** прогнать готовую модель и получить MIDI — это работает отлично уже сегодня.

Поэтому стратегия такая: сначала полезный результат (workflow 2), потом эксперимент (workflow 1), а если захочется качества — те же скрипты уезжают на бесплатный GPU в Colab/Kaggle.

## 1. Быстрый старт

1. Залей эту папку в свой репозиторий на GitHub (можно прямо с телефона через веб-интерфейс).
2. Вкладка **Actions** → workflow **«2. mp3 → midi (готовая модель)»** → **Run workflow**.
3. Варианты, откуда взять песню:
   - закинуть mp3 в папку `input/` (тогда workflow сам стартует на push), или
   - вставить прямую ссылку в поле `audio_url`.
4. Через 3–5 минут внизу страницы запуска, в разделе **Artifacts**, лежит `midi-<номер>.zip` с `.mid`.

Локально то же самое:

```bash
pip install -r requirements.txt
pip install basic-pitch==0.4.0 --no-deps
python scripts/infer.py song.mp3 -o midi/
```

## 2. Обучение своей модели

**Actions** → **«1. Обучить свою модель»** → **Run workflow**.

Параметры (все с дефолтами, можно ничего не менять):

| Параметр | Смысл |
|---|---|
| `minutes` | сколько минут учить (300 по умолчанию) |
| `tracks` | сколько произведений MAESTRO взять (60) |
| `max_seconds` | сколько секунд с каждого (120) |
| `batch_size` | 8 |
| `learning_rate` | 0.001 |
| `steps_per_epoch` | 200 |
| `init_from_url` | ссылка на `checkpoint.tar.gz` из прошлого запуска — продолжить обучение |

Что происходит внутри:

1. ставится TensorFlow 2.15, fluidsynth и саундфонт;
2. качается **MIDI-часть MAESTRO** (57 МБ — живые исполнения пианино);
3. каждый MIDI рендерится в аудио саундфонтом → пары «аудио ↔ ноты»;
4. обучается модель Basic Pitch (≈17k параметров, CQT + свёртки) на окнах по 2 секунды;
5. по истечении `minutes` обучение останавливается **само** и сохраняет чекпойнт;
6. модель экспортируется, на двух треках делается демо (`demo/*.wav` + `*.mid`), всё уходит в артефакты;
7. чекпойнт публикуется в релиз `ckpt-<номер>` — его ссылку можно вставить в `init_from_url` следующего запуска и учить дальше (6 часов × N запусков).

Почему синтез, а не настоящие записи: полный MAESTRO с аудио — 108 ГБ, на раннер столько не влезет. Синтез даёт идеальное выравнивание и бесконечные данные, цена — домен только «пианино, синтезированное fluidsynth».

---

## 3. Что реально получится

После ~5 часов на 4 ядрах (≈8–15 тыс. шагов, ≈30–60 часов аудио):

- модель начнёт уверенно находить ноты в **синтезированном пианино**;
- на реальных записях качество будет плохим — она не видела реверберацию, шум, живые тембры;
- `val_loss` начнёт падать в первые минуты — это и есть проверка, что пайплайн живой;
- `demo/<имя>_predicted.mid` vs `demo/<имя>_reference.mid` — можно сравнить на слух.

Для сравнения: официальная Basic Pitch (в workflow 2) — это та же архитектура, но обученная на ~300 часах реальных данных на GPU. Разница в качестве будет огромной, и это нормально.

---

## 4. Как получить качество выше

Те же скрипты, другая машина:

- **Colab / Kaggle** (бесплатный T4/P100): скопировать репозиторий, `pip install -r requirements.txt`, затем вместо синтеза подать настоящий MAESTRO (`maestro-v3.0.0.zip` уже распакованный, `.wav` + `.midi` парами) — для этого в `prepare_data.py` есть `--midi-dir`, а рендер просто пропускается.
- **Дообучение с готовых весов** — следующий логичный шаг: у Basic Pitch в pip-пакете лежит SavedModel; написать загрузку весов в Keras-модель и учить `lr=1e-4` на своих данных. Это самое выгодное вложение времени, если хочется реального качества.
- **Больше данных**: `--tracks 200 --max-seconds 300` (следи за диском: ~4–5 ГБ npz).

## 5. Файлы

```
.github/workflows/train.yml   обучение (workflow_dispatch)
.github/workflows/infer.yml   mp3 → midi (push в input/ или вручную)
scripts/prepare_data.py       MAESTRO MIDI → fluidsynth → .npz (аудио + ноты)
scripts/common.py             MIDI → onset/note/contour, нарезка окон
scripts/train.py              обучение с лимитом по времени + экспорт модели
scripts/infer.py              аудио → MIDI (своя или готовая модель)
scripts/make_demo.py          демо: wav + предсказанный и эталонный midi
scripts/report.py             итоги в GitHub Step Summary
requirements.txt              пины зависимостей (TF 2.15 — предел для basic-pitch 0.4.0)
```

Локальный прогон без GitHub:

```bash
python scripts/prepare_data.py --out data --tracks 10 --max-seconds 60
python scripts/train.py --data data --out out --minutes 20 --steps-per-epoch 50
python scripts/infer.py demo/track.wav -o midi/ --model-path out/saved_model
```

## 6. Мелкие грабли, о которых стоит знать

- `basic-pitch` ставится с `--no-deps`: иначе pip тянет `tflite-runtime` (только для Python < 3.11) и падает.
- TensorFlow должен быть **2.15.0** — с 2.16 basic-pitch 0.4.0 не собирается.
- mp3 декодируется через `ffmpeg`; в workflow он ставится, локально нужен в системе.
- `prepare_data.py` берёт случайный кусок с каждого трека — так модель видит разные места произведения, а не только начало.
- Если джоб упал на этапе обучения, чекпойнт прошлой эпохи всё равно лежит в артефактах (`out/checkpoints`).
